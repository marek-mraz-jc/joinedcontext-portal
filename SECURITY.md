# Reporting a security issue

Please do not open a public issue for a security problem. Report it privately through this
repository's [GitHub security advisories](../../security/advisories/new), which reaches the
maintainers and nobody else.

Tell us what you can reach and how, on the smallest example that shows it. A proof of concept
against your own installation is welcome; please do not test against somebody else's.

## What is in scope

This repository is the management application, so the answers that matter most are:

- **a permission that is not checked** — a route, an operation, an assistant tool or an MCP
  tool that does something the caller's roles do not allow, or that offers it in a listing it
  would then refuse;
- **a session** — anything that lets one person act as another, keeps a session alive past a
  logout, or accepts a request a browser made on another site's behalf;
- **a secret** — anything that returns, logs or stores a credential rather than naming it by
  `secretRef`, including a value read back out of a draft or an export;
- **the UI** — markup that reaches the page from data rather than from the code that wrote
  it, or a generated application that is served with more access than its manifest declares.

Out of scope: the availability of a demo installation, a report generated by a scanner with no
reachable path behind it, and anything that needs an account the organization already trusts.

## What we do with a report

We confirm receipt, reproduce it, and tell you what we found. A fix lands with a test that
would have caught it, and the advisory names you unless you would rather it did not.
